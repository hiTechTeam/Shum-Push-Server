# Shum Push Server

[English](README.md) · Русский

Шлюз APNs для [Shum](https://github.com/hiTechTeam/Shum-iOS). Регистрирует токены устройств и отправляет уведомления без содержимого сообщений.

## Работа с данными

Сервер хранит соответствия Shum ID и токенов APNs. Запросы записи содержат подписанную публичную карточку: она нужна для проверки запроса и не сохраняется.

Во время обработки уведомления доступны ID отправителя и получателя, ID события и его тип. Эта связь не сохраняется и не записывается в журнал. IP остаётся в памяти для ограничения запросов. Текст сообщений, вложения и приватные ключи сервер не получает.

APNs содержит очищенное имя отправителя, общий локализованный текст, ID и тип события. Текста сообщения и выбранной реакции нет, бейдж приложения не меняется. Недействительные токены и токены, удалённые приложением, удаляются.

## API

| Запрос | Назначение |
| :--- | :--- |
| `GET /healthz` | Проверка процесса |
| `GET /readyz` | Готовность настроек APNs |
| `GET /invite` | Страница приглашения |
| `POST /v1/devices` | Регистрация токена |
| `DELETE /v1/devices` | Удаление токена |
| `POST /v1/notifications` | Запрос уведомления |

Запись использует Ed25519 и заголовки `X-Shum-Public-Key`, `X-Shum-Timestamp`, `X-Shum-Nonce`, `X-Shum-Signature`. Подписываются метод, путь, время, nonce и SHA-256 точного тела запроса. См. [протокол](https://github.com/hiTechTeam/Shum-Protocol/blob/main/spec/08-push-api.md).

## Ссылки контактов

`https://<gateway-host>/invite#c4/<signed-profile>` открывает самодостаточное приглашение `shum://c4/<signed-profile>`. Фрагмент остаётся в браузере; на странице нет аналитики и внешних скриптов. Принимаются приглашения ограниченного размера, перенаправления на произвольные URL нет.

Карточки c4 содержат ключи, имя и seed аватара для добавления офлайн в совместимых клиентах. Старые приглашения c2, c и c3 поддерживаются. Это страница браузера, не iOS Universal Link. Направьте `GET /invite` через HTTPS-шлюз.

## Запуск

Скопируйте [server.env.example](deploy/server.env.example) в `/etc/shum-push/server.env`. Укажите отдельные ключи APNs .p8 и Key ID для Sandbox и Production, Team ID и bundle ID. Публичный HTTPS завершайте на прокси или шлюзе.

```sh
go test ./...
node --test internal/api/invitation.test.cjs
go run ./cmd/shum-push-server
```
